本書は VLat(アニメ調人型3Dアバターへの視点依存表現拡張基盤)の要件定義である。設計判断の根拠は `00_EVALUATION_AND_DECISIONS.md`、データ形式は `02_FORMAT_SPEC.md`、構成は `03_ARCHITECTURE.md` を参照。

## 1. 目的とスコープ

### 1.1 目的
既存のアニメ調人型3Dアバター(VRM)に対し、視点依存の見え(形状補正・可視性・透明度・マテリアル状態・描画順)を**非破壊の差分レイヤ**として記述・編集・保存・再生・ベイク出力できる制作基盤一式を提供する。

### 1.2 成果物(4点セット)
1. **VLatフォーマット**: `.vlat.json` + `.vlat.bin` の仕様と JSON Schema、C#データモデル
2. **VLatエディタ**: Unity エディタ拡張(UI Toolkit)
3. **VLatランタイム**: Unity ランタイムライブラリ(Play Mode / ビルドアプリで動作)
4. **ベイクエクスポータ**: 代表角度ブレンドシェイプ・マテリアルプリセットの書き出し

### 1.3 対象ユーザー
VRMアバターを自ら制作・改変できる一般クリエイター(Unity と UniVRM の基本操作ができる層)。

### 1.4 スコープ内(初期開発)
- 対象部位: 頭部周辺(前髪・横髪・髪/瞳ハイライト・顔輪郭)。※データ形式自体は部位非依存で設計する
- VRM 1.0 の読み込み・編集・再生、VRM 0.x の読み込み
- Built-in Render Pipeline + MToon
- 単一評価カメラ

### 1.5 スコープ外(非目標)
- 新規レンダラー・新規変形理論の開発
- VRChat内での専用ランタイム動作(技術的に不可能。ベイク経路のみ)
- URP/HDRP 対応(将来課題)
- 複数カメラ同時のマルチビュー整合
- 全身への視点依存変形(形式上は可能だがUI・検証は頭部優先)
- リグ・ボーン構造自体の変更

## 2. 用語
| 用語 | 定義 |
|------|------|
| AngleBand | yaw/pitch 空間上の矩形領域+遷移幅。補正の有効範囲 |
| Modifier | 1つの補正(vertexDelta / visibility / opacity / materialProperty / renderQueue) |
| Layer | 部位単位で Modifier 群と AngleBand をまとめた編集単位 |
| VLatドキュメント | 1アバターに対する差分ファイル一式 (`.vlat.json` + `.vlat.bin`) |
| 評価カメラ | 角度算出に用いる単一のカメラ |

## 3. 機能要件 (F)

### F-1 フォーマット・I/O
- **F-1.1** `.vlat.json` の読み込み・書き出し。JSON Schema によるバリデーション(不正時は行番号つきエラー)。
- **F-1.2** 頂点差分等の大容量データは `.vlat.bin` に格納し、glTF様式の bufferView で参照する。
- **F-1.3** シリアライズ往復(load→save→load)で意味的に同一なドキュメントが得られること。
- **F-1.4** バージョンフィールド(semver)を持ち、前方互換の警告機構を持つこと。
- **F-1.5** 対象メッシュ・マテリアルの参照はヒエラルキーパス+コンテンツハッシュの二重化で行い、アバター側の軽微な変更に対して再バインド支援を行う(→02 §4)。

### F-2 ランタイム
- **F-2.1** VRMアバター(UniVRMでロード済み)+ VLatドキュメントを与えると、毎フレーム評価カメラの yaw/pitch に応じて補正を適用する。
- **F-2.2** 合成順序は 00 §2.2 のパイプラインに従う。
- **F-2.3** vertexDelta は動的追加ブレンドシェイプとして実装し、CPU毎フレーム頂点書換を行わない。
- **F-2.4** AngleBand 間の遷移は smootherstep 補間。priority による占有と同priority正規化ブレンドをサポート。
- **F-2.5** visibility 系はオプションのヒステリシスをサポート。
- **F-2.6** VLatの適用有効/無効をランタイムで即時切替できる(Before/After比較用)。
- **F-2.7** VRM Expression(表情)の任意状態と併用して破綻しない(表情×角度の組合せテストで確認)。

### F-3 エディタ
- **F-3.1** VRMアバターのロードと、新規/既存 VLatドキュメントの作成・保存・再読み込み。
- **F-3.2** Layer / AngleBand / Modifier の CRUD をリスト+インスペクタUIで提供。
- **F-3.3** **マルチビュープレビュー**: 正面・斜め45°・横などプリセット角度+任意角度の同時表示(最低3ビュー)。編集結果が全ビューへ即時反映。
- **F-3.4** **角度スクラブ**: yaw/pitch スライダで評価角度を連続的に動かし、遷移を確認できる。
- **F-3.5** **3D直接編集** (Phase 2): 頂点選択(ブラシ/矩形)→ ソフト選択つき移動ハンドルで vertexDelta を作成・編集。
- **F-3.6** **2Dワープ編集** (Phase 3): 現在視点へ投影した2Dキャンバス上でハンドルドラッグ→深度保存逆投影+Laplacian平滑化で vertexDelta 化。遮蔽頂点は除外。
- **F-3.7** 非形状 Modifier(可視性・透明度・マテリアルプロパティ・描画順)のプロパティ編集UI。
- **F-3.8** Unity 標準の Undo/Redo に全編集操作が統合されること。
- **F-3.9** 未保存変更がある状態での破棄操作には確認ダイアログを出すこと。

### F-4 ベイク出力
- **F-4.1** 指定角度リストにおける vertexDelta 合成結果を、名前付きブレンドシェイプとして VRM(glTF morph target)へ書き出す。
- **F-4.2** 各 AngleBand のマテリアル状態をマテリアルアセット/テクスチャとして書き出す。
- **F-4.3** ベイクで失われる情報(連続遷移・ヒステリシス等)を一覧するベイクレポートを出力する。

### F-5 サンプル・ドキュメント
- **F-5.1** 視点依存表現の効果が分かるサンプルVRMアバター(再配布可能ライセンス)と、前髪・ハイライト・輪郭補正を含むサンプル `.vlat.json` を同梱。
- **F-5.2** デモシーン(角度スクラブ+Before/After切替)を同梱。
- **F-5.3** README / フォーマット仕様書 / チュートリアルを日英で用意(日本語優先)。

## 4. 制約条件 (C)
- **C-1** Unity 2022.3.62f3 / Built-in RP / UniVRM (VRM 1.0) / UI Toolkit / C# 9。
- **C-2** 元のVRMファイル・元アセットを一切変更しない(非破壊)。ベイクは常に別ファイルへ出力。
- **C-3** 公開前提（開発中は PolyForm Strict 1.0.0、完成後に MIT などへ変更する想定）。実行時の外部依存は UniVRM, UnityEngine,
  Unity公式 `com.unity.nuget.newtonsoft-json` に限定する。テストでは Unity Test
  Framework と、配布物に含めない JSON Schema 検証ツールのみを追加可とする。
- **C-4** すべての公開APIに XML doc コメント。asmdef によるモジュール分割(→03)。

## 5. 非機能要件 (NFR)
- **NFR-1 性能(ランタイム)**: 参照機(RTX 3060 Ti / i7-12700F)で、頂点数7万・Layer数20・Modifier数60 のアバター1体あたり、VLat評価のCPUコストが **0.3 ms/frame 以下**。GC割当は定常状態で **0 B/frame**。
- **NFR-2 性能(エディタ)**: 3ビュー同時表示で編集操作のUI応答が 100 ms 以内。
- **NFR-3 容量**: 頭部差分中心の典型ドキュメントで `.vlat.bin` が 5 MB 以下(スパース頂点格納を必須とする)。
- **NFR-4 信頼性**: 不正な `.vlat.json` を読んでもエディタ/ランタイムがクラッシュしない。
- **NFR-5 保守性**: フォーマット仕様(02)とC#実装の乖離をテストで検出できること(Schemaテスト)。

## 6. テスト要件 (T)
- **T-1** シリアライズ往復テスト(F-1.3)と JSON Schema 適合テスト(EditMode)。
- **T-2** 角度評価ユニットテスト: yaw/pitch算出、バンド重み、priority占有、ヒステリシスの境界値テスト。
- **T-3** ゴールデンイメージテスト(PlayMode): サンプルアバター×固定角度セット(正面/±45°/±90°/仰俯角±30°)でレンダリング結果を基準画像と比較(許容差分閾値つき)。
- **T-4** 性能テスト: NFR-1 の計測ハーネス(Unity Profiler API / PerformanceTesting パッケージ)。
- **T-5** ベイク検証: ベイク出力VRMを再ロードし、代表角度での見えがランタイム版と閾値内で一致すること。

## 7. 受け入れ基準(初期開発の最終デモ)
1. サンプルVRMを読み込み、前髪・横髪・ハイライト・顔輪郭の視点依存補正を **エディタ上で新規作成→保存→再読込→再生** する一連の流れをライブ実演できる。
2. 角度スクラブで遷移が滑らかであり(チャタリングなし)、表情変化と併用しても破綻しない。
3. ベイク出力したVRMを素のUniVRM環境で開き、代表角度ブレンドシェイプが機能する。
4. T-1〜T-5 が CI(GitHub Actions, Unityライセンスはactivationファイル方式)でグリーン。
