# 保存の仕組み

Kakudoll は `.vlat.json` と `.vlat.bin` の 2 つのファイルに保存します。
この文書では、保存の途中で Unity や PC が落ちたときに何が起きるかと、守れないことを説明します。

## 守られること

- 保存中に落ちても、次に Kakudoll Editor でそのファイルを開くと、保存前か保存後のどちらかの状態に戻ります。
  `.vlat.json` と `.vlat.bin` が食い違ったまま使われることはありません。
- 書き込みに失敗したとき（権限がない、ディスクがいっぱい、ファイルが使用中など）は、元のファイルをそのまま残します。
- 同じファイルを 2 つの Unity から同時に保存しようとすると、後から始めた方が何も書かずに失敗します。
- Kakudoll の外でファイルが書き換えられていたら、上書きせずに知らせます。

## 守れないこと

- **前の状態には戻せません。** 保存は上書きで、古い内容は残りません。大事なファイルはバックアップを取るか、Git で管理してください。
- 電源が落ちた場合は、ファイルシステムやディスクの設定によっては、最後の書き込みがディスクに残らないことがあります。
- 保存中に別のプログラムがファイルを消したりロックしたりすると、失敗として扱いますが、内容を守れるとは限りません。

Editor の自動復元（`Library/VLat/`）は、**まだ保存していない編集**を Unity の異常終了から戻すための機能です。保存したファイルの古い版を残すものではありません。

## 表示されるメッセージ

| メッセージ | 意味と対処 |
|---|---|
| 「前回の保存が途中で中断され…」 | 保存が途中で止まり、2 つのファイルの内容が合っていません。Kakudoll Editor で開くと保存前の状態に戻ります |
| 「前回の保存は反映前に中断されています」など（警告） | 保存は途中で止まりましたが、ファイルは食い違っていません。そのまま使えます。Editor で開くと一時ファイルを片付けます |
| 「別の処理がこのファイルを保存中です」 | 別の Unity が同じファイルを保存しているところです。終わってから開き直してください。どこでも保存していないのに続く場合は、PC を再起動してください |
| 「保存ジャーナルが壊れているため、自動では復旧しません」 | 下の「手で直すとき」を見てください |

### 手で直すとき

`.vlat.json` と同じフォルダに、ドットで始まる次のファイルがあります。

- `.<名前>.vlat.json.vlat-save-journal`: 保存の記録
- `.<名前>.<ID>.bak`: 置き換える前のファイル
- `.<名前>.<ID>.tmp`: 書きかけの新しいファイル

`.bak` を手元のバックアップと見比べ、残したい方を元の名前に戻してから、ジャーナルを削除してください。

## 仕組み（開発者向け）

`VlatSerializer.Save` は次の順に書き込みます。Editor の保存も同じです。

1. 保存ジャーナルを書く。書き込む予定のファイル、一時ファイルの名前、新しい内容の SHA-256 を記録する。
   一時名で書き終えてから名前を変えるので、書きかけのジャーナルは残らない。保存が終わるまで開いたままにして、ロックとして使う。
2. 新しい内容を一時ファイルに書き、ディスクへ flush する。
3. `.vlat.bin` を一時ファイルで置き換える。元のファイルは `.bak` として残す。
4. `.vlat.json` を置き換える。
5. ジャーナルを消す。ここで保存が確定する。
6. `.bak` を消す。

ジャーナルが残っていると、`VlatSerializer.Load` は記録した SHA-256 とファイルを比べます。
bin の長さが同じでも、古い JSON と新しい bin の組み合わせを見分けられます。

| ファイルの状態 | `Load` | Editor で開いたとき |
|---|---|---|
| まだどれも置き換わっていない | 警告を出し、保存前の内容を読む | 一時ファイルを片付ける |
| bin だけ置き換わった | エラー | 保存前の内容に戻す |
| 全部置き換わった | 警告を出し、保存後の内容を読む | 一時ファイルを片付ける |
| 別の処理が保存中 | エラー | 開かない |

Editor 以外からは `VlatSerializer.RecoverInterruptedSave(jsonPath)` で同じ復旧ができます。Runtime（`VlatApplier`）は読むだけで、復旧はしません。
5 と 6 のあいだで落ちたときは、保存後の内容が正しく読め、`.bak` が残るだけです（消してかまいません）。

## 確かめたこと

- Core の単体テストと Unity EditMode で、保存の各段階で止めた場合、権限不足、ディスク不足、同時保存、壊れたジャーナルを試しています（`VlatFileSafetyTests`）。
- 保存中のプロセスを実際に強制終了する試験（`tests/CoreHarness/SaveCrash`）を Linux で 500 回行い、復旧後はすべて保存前か保存後のどちらかに一致しました。CI でも毎回 50 回実行しています。
- 実際の電源断、ネットワークドライブ、macOS では試していません。
