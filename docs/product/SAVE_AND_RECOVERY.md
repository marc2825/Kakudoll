# 保存の仕組みと、データを守れる範囲

2026-11-22（Issue #6）。Kakudoll の保存で何が守られ、何が守られないかをまとめます。

## 先に結論

- 保存中に Unity が落ちても、**次に Kakudoll Editor で開けば、保存前か保存後のどちらか一方の内容に戻ります**。
  `.vlat.json` と `.vlat.bin` が別々の版のまま開かれることはありません。
- ただし、これは「1回の保存が中断されたとき」の保護です。**前の版に戻す機能はありません。**
  大事なファイルは、保存する前に複製するか、Git などで版を管理してください。
- Editor の自動 Recovery（`Library/VLat/`）は、**まだ保存していない編集**を Editor の異常終了から戻すためのものです。
  保存したファイルの版を管理するものではありません。

## 保存の順序

`VlatSerializer.Save` は次の順に書き込みます。Editor の「保存」も同じ処理です。

1. 保存ジャーナル `.<名前>.vlat.json.vlat-save-journal` を作る（書き込む予定のファイル、一時ファイル名、新しい内容の SHA-256）。
   同じ名前のジャーナルがすでにあれば、保存を始めない。
2. 新しい内容を一時ファイル `.<名前>.<ID>.tmp` に書き、ディスクへ書き出す（flush）。
3. `.vlat.bin` を一時ファイルで置き換える。元のファイルは `.<名前>.<ID>.bak` に残す。
4. 最後に `.vlat.json` を置き換える。
5. ジャーナルを削除する。**ここで保存が確定する。**
6. `.bak` を削除する。

ドットで始まる一時ファイルは、Unity の Asset Database からは無視されます。

## 失敗のしかたと結果

| 状況 | 何が起きるか | 確認しているテスト |
|---|---|---|
| 書き込み権限がない、ディスクがいっぱい、ファイルが使用中 | 書き込みを元に戻し、ジャーナルも消す。元のファイルは変わらない | `Save_IoFailureRollsBackWithoutJournal`、`Save_CommitFailureRestoresExistingBuffer` |
| 1〜4 の途中で Unity・PC が落ちた | ジャーナルが残る。次回の読み込みで検出する（下の表） | `Save_CrashAtEachStepIsDetectedAndRecoverable`、`tests/CoreHarness/SaveCrash` |
| 5 と 6 のあいだで落ちた | 保存後の内容が正しく読める。`.bak` が残るだけ（削除してよい） | `Save_CrashAfterCommitPointLeavesOnlyBackupFiles` |
| 同じファイルを2つの処理が同時に保存した | 後から始めた方は何も書かずに失敗する | `Save_ConcurrentSaveIsRejected` |
| 保存の途中で元に戻す処理まで失敗した | ジャーナルを残し、次に開くときに復旧を再試行する | — |
| Editor の外でファイルが書き換えられた | Editor は上書きせず、競合として知らせる（開き直すか別名で保存） | 既存の保存元指紋の試験 |
| bin の置き場所がシンボリックリンク経由 | 安全モードでは保存しない | `SafeMode_RejectsPathsThroughLinks` |

ジャーナルが残っているファイルを読み込んだときの扱い:

| 状態 | `VlatSerializer.Load` | Kakudoll Editor で開く |
|---|---|---|
| どのファイルもまだ置き換わっていない | 警告つきで保存前の内容を読む | 一時ファイルを片付けて開く |
| bin だけ置き換わり、JSON は古い | **エラー**（組み合わせが一致しない） | 保存前の内容へ戻して開く |
| 全部置き換わったが、ジャーナルが残った | 警告つきで保存後の内容を読む | 一時ファイルを片付けて開く |
| 別の処理が保存中 | エラー | 開かない（保存が終わってから開き直す） |

判定には、ジャーナルに記録した新しい内容の SHA-256 を使います。
bin の長さが同じでも、古い JSON と新しい bin の組み合わせを見分けられます。

Editor 以外のコードからは `VlatSerializer.RecoverInterruptedSave(jsonPath)` で同じ復旧ができます。
Runtime（`VlatApplier`）は読むだけで、復旧はしません。

## 保証できないこと

- **前の版への巻き戻し。** 保存が確定したら、前の内容は残りません。
- **電源断のときのファイルシステムの動作。** 一時ファイルは flush しますが、置き換え（rename）がディスクに残るかどうかは、
  ファイルシステムとディスクのキャッシュ設定に依存します。フォルダの flush はしていません。
- **壊れた・書き換えられたジャーナル。** 形式が合わない、許可フォルダの外を指す、一時ファイル名が規則と合わない
  ジャーナルでは、自動では何もしません（「保存ジャーナルが壊れているため…」と表示されます）。
- **他の処理による妨害。** 保存中に別のプログラムがファイルを消す・ロックするなどの場合は、上の表のとおり失敗として扱いますが、
  内容を守れるとは限りません。

## 確認した環境

| 試験 | 環境 | 結果 |
|---|---|---|
| 各段階での中断（例外で模擬）・権限不足・容量不足（模擬）・同時保存・改ざんジャーナル | .NET 10 / Linux（Core NUnit）、Unity 2022.3.62f3 / Windows 11（EditMode） | PASS |
| 実プロセスの強制終了 100 回（`tests/CoreHarness/SaveCrash`） | .NET 10 / Linux（WSL2）、2026-11-22 | 100 回とも復旧後に保存前か保存後のどちらかに完全一致。失敗 0 |
| 実際の電源断、ネットワークドライブ、macOS | — | **未実施** |

`SaveCrash` は次のように実行できます（数十秒かかります）。

```bash
dotnet run -c Release --project tests/CoreHarness/SaveCrash/SaveCrash.csproj -- 100
```

## うまくいかないとき

- 「前回の保存が途中で中断され…」と表示された: Kakudoll Editor でそのファイルを開くと、保存前の内容へ戻ります。
- 「保存ジャーナルが壊れているため、自動では復旧しません」: JSON と同じフォルダにある
  `.<名前>.vlat.json.vlat-save-journal` と `.<名前>.*.bak` / `.tmp` を確認してください。
  `.bak` は置き換える前のファイルです。手元のバックアップと比べてから、ジャーナルを削除してください。
- 「別の処理がこのファイルを保存中です」: 別の Unity が同じファイルを開いていないか確認してください。
  どこでも保存していないのに続く場合は、PC を再起動してから開き直してください。
