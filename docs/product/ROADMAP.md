# ROADMAP

Keyform v0.2 をゲーム実行中に再生し、VRChat で使えるようにするまでの計画です。
今は Pre-beta で、Unity エディタの中でしか動きません。ここに書いたことは、どれも公開前に必須の作業ではありません。

## 今の状態

| 機能 | 状態 |
|---|---|
| Yaw ごとの Keyform の編集・プレビュー・保存（v0.2） | できている（Windows / Unity 2022.3.62f3 の自動テスト） |
| Keyform の CPU での参照計算（`KeyformReferenceEvaluator`） | できている。編集と検証用で、毎フレーム動かすものではない |
| v0.1 形式のゲーム実行中の再生（`VlatApplier`） | できている。カメラは 1 台だけ |
| Keyform v0.2 のゲーム実行中の再生 | 未実装（`VlatApplier` は Keyform のファイルを受け付けない） |
| GPU での変形 | 未実装。頭の向きと視点を取る実験用 Shader だけある |
| 頭の向き・Stereo・Mirror の扱い | Unity エディタ内の模擬では動いた。VRChat では未確認 |
| VRChat クライアント・HMD での動作 | 未確認（[実機確認の準備](../experiments/VRC_P0_S2_CLIENT_VALIDATION.md)はしてある） |
| Pitch、法線・接線、複数メッシュ、LOD | 未実装 |

状態は「できている」「Unity 内の模擬では動いた」「未確認」「未実装」の 4 つで書きます。
VRChat で確かめるまでは「VRChat 対応」とは書きません。

## 段階

前の段階の条件を満たしてから次へ進みます。うまくいかない条件に当たったら、その段階で止めて理由を残し、やり方を変えるか見送ります。
数値の基準は測る前に決め、結果を見てから変えません。

### 1. プレビューと参照計算を突き合わせる

- やること: エディタのプレビューの頂点位置を、参照計算と、別に手で計算した値の両方と比べる。Yaw の向き、±180° をまたぐ場合、範囲の端の扱いを決める。
- 進む条件: 合成メッシュと公開されているサンプルモデルで、キーの位置と中間点の差が 1e-6 m 以下。決めた座標系のルールを文書にする。
- 止める条件: 差の原因を説明できない。

### 2. ゲーム実行中に GPU で変形する（メッシュ 1 つ、カメラ 1 台、Yaw だけ）

- やること: 頂点 Shader か Compute Shader で、見る角度に応じた変形をする最小の実装を作る。元のメッシュは書き換えない。
- 進む条件: Windows のビルドで描いた結果を読み戻し、段階 1 の参照計算との差が 0.1 mm 以内。7 万頂点での負荷を測って記録する（CPU は 0.3 ms 以下が目安）。
- 止める条件: 元のアセットを書き換えないと実現できない、または差が基準に収まらない。

### 3. 複数のカメラと、同時に見ている複数の人

- やること: 見る人ごとに違う形を描けるかを確かめる。VR の左右の目は同じ位置で計算する。
- 進む条件: カメラ 2 台以上、Stereo、Mirror で、それぞれの描画がその視点の参照計算と一致する。
  CPU で 1 つのメッシュを書き換えるやり方は、全員に同じ形が見えるので、この段階の答えにはしない。
- 止める条件: 描画ごとに視点を分けられない。その場合は「見る人が 1 人のときだけ対応」と書いて先へ進むか、見送る。

### 4. VRChat の制約を調べる

- やること: VRChat SDK のバージョンを決め（今の記録は 3.10.5）、合成アバターで次を試す。全 Pass（Outline、Shadow、Depth など）、Head Chop、PhysBone、GPU skinning、lilToon・NDMF・Avatar Optimizer との組み合わせ。
- 進む条件: 組み合わせごとに、動いた・動かない・未確認と、動かない理由を記録する。SDK の改変や再配布など、VRChat の規約に反する方法は使わない。
- 止める条件: 必要な Pass で視点が取れない、Head Chop で頭の基準が崩れる、主要な Shader と一緒に使えない。理由と、もう一度試す条件を書いて残す。

### 5. VRChat とヘッドセットで確かめる

- やること: [準備してある手順](../experiments/VRC_P0_S2_CLIENT_VALIDATION.md)（V1〜V10）で、撮影と数値の比較をする。
- 進む条件: 実機での結果を Unity 内の模擬とは分けて記録し、すべて動く。
- 止める条件: 実機でだけ起きる違いを説明できない。ここを通るまで「VRChat 対応」とは書かない。

### 6. その先

次のものは、取りかかるときに別の Issue にして、進む条件と止める条件を決めます。

- Pitch（上下の向き）での切り替え
- 法線・接線の差分、または再計算
- 複数のメッシュ・グループの同時編集
- LOD
- 大きなメッシュでの速さ（今は 13 万頂点で、確定や元に戻すのに 0.2〜0.3 秒）
- v0.1 の Layer との組み合わせ

段階を始めたときと終えたときは、Issue に結果を書き、この文書の「今の状態」を更新します。
